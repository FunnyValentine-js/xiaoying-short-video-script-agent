# 05 复盘

## 最难的问题

**如何让「模型决策」可离线验证又不自欺欺人。** 直接把流程写成固定 if-else 最容易，
但那就是题目明确不认可的「固定条件分支」。最终做法是把决策收敛到
`model.decide(task, state)` 单点：循环骨架不含任何业务分支，Mock 与真实模型实现同一接口。
这样 Mock 能确定性回归测试流程，接上真实模型后决策又完全由模型做出，边界清晰。

其次是如何让时长修正在 trace 里「看得见」：要求 revise 之后必须重新估算（清状态强制走
estimate），并在 observation 里带上各分镜秒数与目标秒数，审核者可以直接核对
「45 秒 → revise → 21 秒」这条调整链。

## 学习收获

- ReAct 的关键不在「循环」，而在观察结果**真的改变**下一步动作，且失败状态要显式
  （`failed_tool` / `failed_no_material` 而非笼统的 error）；
- 步数上限与未完成状态是 Agent 工程的必需品，不写就会在工具抖动时死循环；
- 「不编造事实」要靠机制保证（旁白只从素材 facts 拼装 + 规则检查兜底），不能靠提示词自觉。

## 不足与下一步

1. 时长估算粗糙（仅字数/语速）→ 接入真实配音时长或分镜表估算；
2. 关键词检索弱 → 换向量检索，接口不变；
3. Mock 占比高 → 配置密钥用 `--model openai` 跑同一批用例，对比真实模型的决策路径，
   把差异补进评估文档；
4. 规则检查是字符串级 → 增加语义级事实一致性校验（如让模型逐句核对旁白是否被素材支持）；
5. 单 Agent 单轮 → 可扩展创作者对脚本的反馈迭代轮次。

## 实际用时

约 1.5 小时（含 AI 协作、运行验证与文档），核心链路（决策循环 + 4 场景 + 测试）优先完成；
真实模型实测、向量检索未完成，原因与替代方案见上。
